# 五年级期中考试 · 工程交互规格

- 版本：`2026-11-09-midterm-v1.0`（Asia/Shanghai）
- 对齐：`01_题库.json`；学生端只渲染题面，不写答案
- 只定交互与数据口径，不在此任务写应用代码、不开仓库、不推送

---

## 1 整体流程

1. 学生用**班级名单选名**进入（先选班，再搜索或点选姓名）。名单外学生可手动补录；同一 `id` 重复进入恢复同一份答卷。选名用于课堂身份记录，**不是**安全账户认证。
2. 进入后看到轻外壳说明一句（校园算法开放日·期中验收）和五段目录，直接从第一题作答。本卷是期中整卷，**不**要求先通关第1–7课探究站再开考。
3. 主卷 24 题一次呈现或按大题分页均可；若分页，须能返回修改未提交的作答。挑战 4 题在**主卷提交后**解锁，只加分。
4. 提交前只检查「已答／未答」，高亮未答位置；**不显示正误，不给单个选项加黄框、发光或小手指答案**。提交后由**服务端判分**，再显示对错、解析与得分。
5. 保留**首答、最近、历史**三份成绩。达标只看主卷首答。重做不得覆盖首答，也不提高达标判定。
6. 同学生、本应用、本轮次：主卷提交与挑战提交分别去重计分一次；刷新、断网补传不重复加分。

---

## 2 学生端下发字段（提交前）

只下发：`id` `section` `type` `prompt` `stemExtras` `options` `blanks` `pairs` `flow`，以及版式需要的题序、大题名、倒计时提示。

**不得下发**：`answer` `accept` `explain` `misconception` `goals` `remixFrom` `difficulty` `points`（可在提交后回传得分，但解析页之前不算泄题）`tier` 可用于决定是否解锁挑战，不要把「基础／挑战」做成暗示难度的标签给学生看内部目标。

题干、选项、左右连线文案中不得出现 `G1` `K1` `D1` `S1` 等内部代号，也不使用「循环体」一词（题库已规避）。

---

## 3 各题型学生怎么操作

公共规则：以**单击和拖拽**为主；填空是老师点名允许的少量打字。提供「撤回上一步」（不扣分、不清空其他已答）。同一时刻只提示当前操作位置（题区或提交按钮），不提前点亮某个选项。

### 3.1 单选 `single`（S01–S08，挑战 C01–C04）

- 四选一，点卡片即选中，再点可改选。
- 提交前不标对错。
- 答案为选项下标（从 0 起）或与 `options` 顺序一致的索引。

### 3.2 填空／补充句子 `fill`（F01–F04）

- 题干中的 `______` 渲染为短输入框；用中文输入法即可。
- 每空对应 `blanks[].id`。判分先去首尾空格，再与 `accept[id]` 列表比对（全角／半角符号如 `>=` 与 `≥` 都收入 accept）。
- 建议：该题得分＝答对空数／总空数 × 4 分。主卷若改按题计对错，则须全部空格正确才算该题对。
- 不设开放长句，不要求编程代码。

### 3.3 连线匹配 `match`（T01 T02）

- 左侧 4 项、右侧 4 项，**一对一**。点左项再点右项连线，或把右卡拖到左项槽位。
- 已连的右项不再重复占用；提供撤回。
- 答案为 `{ leftId: rightId }`。建议按对给分：每对 1.5 分，全对 6 分。
- 未连完也可暂存；提交主卷时若有未连对，按未答对处理并提示「还有没连上的」。

### 3.4 操作流程图 `flowchart`（FL01–FL04）

| 题 | `flow.kind` | 操作 |
| --- | --- | --- |
| FL01 | `find_error` | 展示节点序列（开始→…→结束），下方四选一指出错处 |
| FL02 | `fill_branch` | 把选项卡点进「条件／是出口／否出口」三个槽；选项卡不预加正确答案高亮 |
| FL03 | `back_edge` | 展示残图，四选一指出回边接到哪里 |
| FL04 | `order` | 三张步骤卡排进三个空槽，可撤回重排 |

FL02 必须支持题库中的 **等价解**：`页数≥20`＋是得章／否没章，或 `页数＜20`＋是没章／否得章。服务端按 `accept` 数组任一匹配即满分；写成 `页数＞20` 不得分。

图框用简洁 CSS／SVG 即可，避免过重动画。节点文案用题库 `flow.preview` / `flow.nodes`，不要另写会泄题的注释。

### 3.5 曾经应用的操作 `app_op`（A01–A06）

- 交互与单选相同（点选一步判断），但题干点名课堂应用（机器人厨房、算法小侦探、汉诺塔实验室、奇趣游园会、生活算法站、分支岛）。
- A03 使用 `stemExtras.visual` 展示三柱状态（文字状态条即可，不必重做 3D 汉诺塔）。不要在未作答前把合法柱位发亮到像「标准答案」。
- 不要求学生重新打开原应用；本卷内独立作答。

## 4 提交、判分与成绩

1. 主卷「交卷」：未答完时弹出未答题号，允许返回；不强制禁止提交（若老师要求必须全答完再交，可再加开关，默认**允许提交但提示未答**）。
2. 服务端用题库 `answer` / `accept` 判分，计算结果：主卷百分制、逐题对错、填空／连线／补图的分项得分、挑战加分。
3. 提交后再把 `explain` 下发给该生；错题解析须说明正确推导和干扰项错因，不出现内部目标编号。
4. 挑战在主卷提交成功后出现；可不做。挑战成绩单独存储，不回写主卷首答。
5. 教师大屏：已进入／作答中／已交主卷／已做挑战；主卷分数分布；分课次正确率（用 `lesson`）；七个应用相关题（S01/A01、F01/A02、…）便于回讲。缺考或未交不记 0 分。

## 5 名单登录说明

- 与第1–7课课堂应用一致：读取受控 `roster`（501–504 等），先选班级再选姓名，支持搜索。
- 正式名单含真实姓名，只放在教师电脑或私有分发包，不进公开材料。
- 示例环境使用虚构名单。手动补录须生成稳定唯一 `id`，更新名单时保留原 `id`。
- 断网时作答保存在当前浏览器，按学生身份隔离；恢复网络后按事件编号去重补传。冲突时不得静默覆盖，应提示导出后核对。

## 6 Win7 Chrome 友好

机房约一半电脑仍是 Windows 7 上的 Chrome。本期中页必须按该环境验收，不得只按新机高配浏览器验收。

| 要求 | 做法 |
| --- | --- |
| 不依赖外网 | 无 CDN、无在线字体、无远程脚本；题面与图框本地提供 |
| 语法与 API | 避免仅新浏览器支持的 JS 语法与 CSS（如过新的 `:has`、过重 `backdrop-filter`）；单击／拖拽用兼容写法 |
| 动效 | 少用或可关；尊重「减少动态效果」；不自动播放音视频 |
| 资源 | 控制图片体积；流程图用简单色块＋文字，不嵌入大型游戏引擎 |
| 视口 | 以机房常见 1024×768、1366×768 为先，避免必须横向滚动才能看到选项 |
| 输入 | 填空框支持系统中文输入法；不要拦截常用按键导致无法打字；Enter 不误触发交卷 |

不在本期中卷重做 Godot／RPG 场景。汉诺塔状态、分支残图、循环回边均用静态框图＋点选完成。

## 7 无障碍与防误导（课堂常驻，择要）

- 未作答选项零高亮，防止被当成标准答案。
- 每种题型顶部一行任务口吻提示（例如「选出对调后会停错的那一组」），不要只写「请选择」。
- 解析弹窗、提示卡须有明显关闭按钮。
- 不在学生页展示教师大屏入口。

---

## 8 给实现方的边界

- 不得改题目、答案、`accept`、达标线或挑战加分规则；不清处交回命题方。
- 题库版本写入答卷记录：`2026-11-09-midterm-v1.0`。
